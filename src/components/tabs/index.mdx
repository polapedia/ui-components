Built for reusability and consistency, following the Polapedia design system.

## Variants

### Underline

The standard navigational tab with an underline indicator.

- **Underline (Default)**: Individual underline per item.
- **Underline Full**: Continuous baseline across all tabs.

## Interaction Modes

The `Tabs` component supports two distinct interaction modes depending on your application's architecture.

### 1. Link Navigation (`href`)

Use this mode when tabs act as a main navigation bar that redirects users to different pages or URLs.

- **How to use**: Provide an `href` in the `tabs` objects and **omit** the `onValueChange` prop.
- **Behavior**: Each tab renders as an `<a>` tag.
- **Best for**: Multi-page applications or external links.

<Canvas of={TabsStories.AsLinks} />

```tsx
const navTabs = [
  { label: 'Home', value: 'home', href: '/home' },
  { label: 'Explore', value: 'explore', href: '/explore' },
];

// Re-renders as <a> tags automatically
<Tabs tabs={navTabs} value="home" />;
```

### 2. Content Switching (`onValueChange`)

Use this mode when tabs are used to toggle visibility of content on the current page without a full reload.

- **How to use**: Provide the `onValueChange` callback prop.
- **Behavior**: Each tab renders as a `<button>`.
- **Best for**: Dashboards, settings panels, or single-page application (SPA) views.

<Canvas of={TabsStories.Primary} />

```tsx
const [activeTab, setActiveTab] = useState('profile');

<Tabs
  tabs={myTabs}
  value={activeTab}
  onValueChange={(val) => setActiveTab(val)}
/>;

// Display content based on activeTab
{
  activeTab === 'profile' && <ProfileView />;
}
```

## Responsive Behavior

...

## Usage Guidelines

- **Labeling**: Use clear, concise labels (e.g., "Overview", "Settings").
- **Consistency**: Stick to one variant per feature/page to maintain UI harmony.
- **Data-Driven**: Use the `tabs` array configuration for easy integration.
